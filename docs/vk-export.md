# Выгрузка картинок из VK

Для «Робота, которому грустно» есть два практических пути. `gallery-dl` подойдёт,
если нужны сами изображения из альбомов или отдельных записей. Скрипт в этом
репозитории сохраняет также текст стены и связь каждой картинки с публикацией.

Документация и исходники проверены 24 октября 2026 года. Запросы к VK и реальная
выгрузка сообщества здесь **не выполнялись**: работоспособность на текущем VK,
доступность постов и полноту архива нужно проверить локальным запуском.

## 1. Готовая утилита gallery-dl

В [официальном списке поддерживаемых сайтов](https://github.com/mikf/gallery-dl/blob/master/docs/supportedsites.md)
для VK перечислены фотографии, альбомы, отмеченные фотографии и **отдельные**
посты стены. В [текущем экстракторе](https://github.com/mikf/gallery-dl/blob/master/gallery_dl/extractor/vk.py)
шаблон адреса поддерживает `vk.com`, включая `m.vk.com`, но не `vk.ru`.
Универсальной выгрузки всей стены по адресу сообщества этот экстрактор не обещает.
Адрес `https://vk.com/sadrobo` выбирает фотографии страницы, а не архив всех
публикаций с текстами. Если нужен другой домен, проверьте поддержку в установленной
версии; простая замена `.ru` на `.com` сама по себе не доказывает доступность.

Команды для PowerShell, из корня репозитория:

```powershell
py -m pip install --upgrade gallery-dl
New-Item -ItemType Directory -Force .cache/vk-export/gallery | Out-Null
py -m gallery_dl --version
```

Проверка одной известной ссылки на пост — замените числовые ID:

```powershell
py -m gallery_dl --simulate "https://vk.com/wall-123456_789"
```

Скачать изображения поста вместе с доступными метаданными:

```powershell
py -m gallery_dl -d .cache/vk-export/gallery --download-archive .cache/vk-export/gallery.sqlite3 --write-metadata "https://vk.com/wall-123456_789"
```

Альбом, фотораздел сообщества или список уже известных ссылок на посты:

```powershell
py -m gallery_dl -d .cache/vk-export/gallery --download-archive .cache/vk-export/gallery.sqlite3 --write-metadata "https://vk.com/album-123456_987654"
py -m gallery_dl -d .cache/vk-export/gallery --download-archive .cache/vk-export/gallery.sqlite3 --write-metadata "https://vk.com/sadrobo"
py -m gallery_dl -d .cache/vk-export/gallery --download-archive .cache/vk-export/gallery.sqlite3 --write-metadata -i .cache/vk-export/posts.txt
```

В `posts.txt` нужна одна ссылка `https://vk.com/wall…_…` на строку. SQLite-архив
учитывает успешно скачанные объекты для повторного запуска; это не сравнение
содержимого разных картинок по хешу. `--write-metadata` сохраняет сведения,
которые смог получить экстрактор, а не гарантированно весь текст архива.
Параметры проверены по [официальной справке CLI](https://github.com/mikf/gallery-dl/blob/master/docs/options.md).

Если VK выдаёт страницу входа или CAPTCHA, остановитесь и проверьте доступ в
своём браузере. Экстрактор зависит от HTML/внутреннего ответа сайта и может
сломаться при изменениях VK. Не сохраняйте cookies и токены в репозиторий.

## 2. Стена с текстом и привязкой фотографий

В проект добавлен собственный `scripts/export_vk.py`, только на стандартной
библиотеке Python 3.10+. Он использует `wall.get`: [официальная схема VK](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json)
описывает короткий адрес `domain`, `offset`, максимум 100 записей и типы токенов
`user` / `service`. Это не означает, что любой такой токен имеет доступ к любой
стене. Нужен ваш собственный действующий токен VK API с правом чтения этой стены,
полученный через разрешённый VK способ авторизации приложения.

```powershell
py scripts/export_vk.py --domain sadrobo
```

Скрипт спросит токен скрытым вводом в интерактивном терминале. Токен не нужно
вписывать в команду, файл, переменную окружения или присылать в чат. Он передаётся
VK в теле HTTPS POST и не попадает в экспорт либо диагностические сообщения.
Если терминал не умеет скрывать ввод, программа откажется принимать токен.

Результат по умолчанию:

```text
.cache/vk-export/
  export.json        тексты, ссылки, даты Unix, связи постов и фото, состояние
  images/            скачанные файлы с именами по SHA-256
```

Каталог `.cache/` уже исключён из Git. Не публикуйте сырой экспорт автоматически:
сначала сверьте публикации с существующим архивом и права на вложения репостов.
Читалка и её контент этим скриптом не изменяются.

Для продолжения после остановки или ошибки запустите ту же команду. Сканирование
снова начинается с начала стены, чтобы увидеть новые записи и обновить ссылки;
посты объединяются по паре `owner_id` / `post_id`, проверенные локальные картинки
повторно не скачиваются. Файлы проверяются по SHA-256; повреждённые и отсутствующие
скачиваются заново. Разные ID фото с одинаковыми байтами используют один файл,
связи с несколькими постами сохраняются. Это точное сравнение файлов, а не поиск
похожих рисунков, пережатых VK или Telegram.

В `export.json` словарь `posts` содержит `text`, `date`, `url`, `photos` и тексты
`reposts`; каждая связь фото указывает `source_post`. Словарь `photos` содержит
источник, максимальный доступный размер, относительный `file` и `sha256`.
Фото берётся из `sizes` / `images` с наибольшей площадью в пикселях, без изменения
CDN-ссылки. [Официальная схема объекта фотографии](https://github.com/VKCOM/vk-api-schema/blob/master/photos/objects.json)
описывает эти размеры; наличие настоящего исходного файла она не гарантирует.
Если доступен только отдельный URL без сравнимых размеров, скрипт не придумывает
разрешение и оставляет фото в списке недостающих для ручной проверки.

`complete: true` означает, что текущий обход завершился и все известные скрипту
фото скачаны. Это не гарантия, что VK открыл все исторические записи. Ошибки
вложений сохраняются в `errors`, недостающие ID — в `missing_photo_ids`; код выхода
при неполной выгрузке равен 1. После сбоя API уже обработанные посты остаются
в файле, а `complete` остаётся `false`.
Пустая страница раньше заявленного VK конца стены тоже считается ошибкой;
сохранённые записи остаются доступны, успешное завершение не отмечается.

Ограничения: читаются записи владельца (`filter=owner`) и фотографии их вложений,
включая доступные вложения репостов; отдельные альбомы без записей на стене,
комментарии, видео, документы, истории, удалённые и недоступные публикации сюда
не входят. Ранее сохранённые посты не удаляются, если VK перестал их отдавать.
Если во время обхода на стене добавляют или удаляют записи, смещения могут
сдвигаться: повторите полный запуск для сверки.

Запросы идут последовательно, с интервалом 0,5 секунды и ограниченным повтором
сетевых ошибок / rate limit. При запрете доступа или CAPTCHA обход API прекращается.
Таймаут запроса — 40 секунд; размер одного изображения ограничен 60 МиБ.
Экспорт не запускается в CI и не требует установки сторонних пакетов.

Офлайн-проверка логики, без обращения к VK:

```powershell
py -m unittest discover -s test -p "test_vk_export.py"
```

# Прямая выгрузка VK: тексты и фотографии

Только VK API и локальный Python 3.10+, без сторонних пакетов, посредников,
платных решений и trial. ВКонтакте — первоисточник; остальные площадки — зеркала.
Правила сверки: [source-policy.md](source-policy.md).

## Какой именно ключ нужен

**Если у вас уже есть пользовательский ключ VK API, используйте его:** тип
`user` прямо поддерживается `wall.get`. Создавать приложение ради другого
ключа в таком случае не нужно.

Второй поддерживаемый вариант для публичной стены — **сервисный ключ доступа
собственного приложения VK Mini Apps**, тип API `service`.

Основания из официальных материалов VK:

- [Схема `wall.get`](https://github.com/VKCOM/vk-api-schema/blob/master/wall/methods.json)
  версии 5.199 перечисляет `access_token_type: ["user", "service"]`.
  Тип `group` у этого метода отсутствует.
- [Официальный Java SDK, WallGetQuery](https://github.com/VKCOM/vk-java-sdk/blob/master/sdk/src/main/java/com/vk/api/sdk/queries/wall/WallGetQuery.java)
  реализует вызов с `ServiceActor` и требует `access_token`.
- [Официальный учебный проект VK Mini Apps](https://github.com/VKCOM/vk-mini-apps-course-backend/blob/main/README.md)
  различает `VKMA_APP_SECRET` (защищённый ключ) и `VKMA_SERVICE_KEY`
  (сервисный ключ) и указывает, что ключи находятся в настройках мини-приложения.
- [VkApiClient официального SDK](https://github.com/VKCOM/vk-java-sdk/blob/master/sdk/src/main/java/com/vk/api/sdk/client/VkApiClient.java)
  использует адрес `https://api.vk.com/method/`.

Ключ сообщества, созданный с правами «сообщения», «фотографии», «файлы»,
«истории», «стена», остаётся ключом `group`. Эти разрешения не превращают его
в ключ `service` и не добавляют его в поддерживаемые типы `wall.get`.
Не предлагайте запуск выгрузки с заведомо неподходящим ключом.

Нужен именно ключ VK API типа `user` или `service`. Токен только для входа
VK ID, ID приложения и защищённый ключ приложения — другие значения.

Подтверждённого официального способа выполнить этот вызов без ключа в изученных
материалах нет. Внутренние анонимные запросы сайта с чужими `client_id` здесь
не используются: их работоспособность для этого архива не проверена.

## Если готового пользовательского ключа нет: сервисный ключ

1. Откройте [кабинет разработчика VK](https://dev.vk.com/ru/admin/create-app).
2. Создайте собственное **мини-приложение VK Mini Apps**, например
   `SadRobo Archive`. Не выбирайте Flash или приложение только для входа VK ID.
3. В настройках мини-приложения найдите **«Сервисный ключ доступа»**.
   Нужен именно он; «Защищённый ключ» — другое значение.
   [Официальная справка по настройкам](https://dev.vk.com/ru/mini-apps/management/settings).

Наличие сервисного ключа у мини-приложения подтверждено официальным проектом
выше. Точное расположение кнопок в текущем кабинете агент не проверял:
встроенный браузер блокирует открытие VK политикой доступа.

Ключ вводится только в локальном терминале при запуске. Его не нужно сохранять
в репозиторий, передавать в командной строке, переменной окружения или чате.

## Проверка реального доступа

Из папки проекта:

```powershell
py scripts/export_vk.py --domain sadrobo --check
```

Вставьте пользовательский или сервисный ключ в скрытый запрос и нажмите Enter. Программа:

- читает первую страницу стены;
- если записей больше 100, читает также последнюю страницу;
- скачивает и проверяет один доступный файл фотографии из этих страниц;
- выводит число записей и результат проверки, не сохраняя выгрузку или ключ.

Код выхода 0 означает, что эти проверки прошли. Код 2 означает, что чтение
получилось, но в выборке нет фотографии либо число записей изменилось во время
проверки. Код 1 — ошибка. Пустая выдача, отказ API и HTML вместо изображения
не выдаются за успешную проверку.

Проверка первых/последних страниц и одного файла подтверждает доступ,
но не полноту исторического архива. Не называйте офлайн-тесты успешным
реальным запросом к VK. Пока реального успешного запроса к SadRobo с действующим
пользовательским или сервисным ключом в этом проекте не было.

## Полная выгрузка

После успешной проверки:

```powershell
py scripts/export_vk.py --domain sadrobo
```

Ключ снова вводится скрыто. Скрипт вызывает `wall.get` с `domain=sadrobo`,
`filter=owner`, `count=100`, `offset=0, 100, …` до конца доступной стены.
Параметры и ключ передаются в теле HTTPS POST прямо на сервер VK.

Текст берётся из `text`, фотографии — из `attachments[].photo`, вложенные
репосты — из `copy_history`. Для каждой фотографии сохраняется вариант с
наибольшей доступной площадью из `sizes` / `images`, без переписывания CDN URL.
Отдельный вызов `photos.get` и отдельный ключ с правом «фотографии» для файлов,
которые уже доступны в этих вложениях, не используются. Поля размеров описаны
в [официальной схеме фотографии](https://github.com/VKCOM/vk-api-schema/blob/master/photos/objects.json).

Результат:

```text
.cache/vk-export/
  export.json     тексты, ID, даты, ссылки, привязка фотографий к постам
  images/         файлы фотографий, именованные по SHA-256
```

`.cache/` исключена из Git. Читалка автоматически не изменяется.
Посты объединяются по `owner_id` / `post_id`; одинаковые байты изображений
используют один файл. При повторном запуске сканирование идёт с начала,
проверенные файлы используются повторно, недостающие скачиваются заново.
После ошибки уже сохранённые данные остаются в каталоге.

`complete: true` означает завершение текущего обхода и сохранение всех
известных скрипту фотографий. Это не доказательство, что VK выдал удалённые,
скрытые или недоступные записи. Сверьте число записей, начало/конец истории,
датировки и выборочные тексты с самим сообществом. Пустая страница раньше
заявленного конца, повтор страницы, CAPTCHA и запрет доступа останавливают обход.

Ограничения: только записи владельца стены и фотографии их вложений, включая
доступные репосты. Отдельные альбомы, комментарии, видео, документы и истории
не входят в выгрузку. При удалении/добавлении постов во время сканирования
смещения могут изменяться — повторите полный обход для сверки.

## Ошибки и проверка реализации

- **5:** ключ не принят или истёк. Проверьте, что ключ введён целиком.
- **27:** ключ сообщества не поддерживается методом; права «стена» это не исправляют.
- **28 / 1051:** ошибка авторизации приложения или неподходящий тип профиля токена.
- **15:** нет доступа к запрошенной стене. Не считайте такой запуск успешным.
- **14:** CAPTCHA; автоматический обход прекращается.

Скрипт не печатает серверные сообщения и параметры запроса, в которых VK может
повторить ключ. Токен не включается в URL, сохранённые данные или диагностику.
Запросы последовательные, с паузами и ограниченным повтором сетевых ошибок и
rate limit. Экспорт не запускается в CI.

Офлайн-проверки, без VK и без действующих ключей:

```powershell
py -m unittest discover -s test -p test_vk_export.py
```
